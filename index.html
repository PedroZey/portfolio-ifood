02 · O que eu já botei no ar

Projetos, sem marketing

Oito peças. Cada uma com o que é, o número que importa e o arquivo que prova. Ordem: dos sistemas centrais aos experimentos de plataforma.

01jasper-service em produção

Java 17 · Spring Boot 3.4.3 · JasperReports · Sentry · HikariCP · Postgres · Docker

Microsserviço de relatórios fiscais multi-tenant: cada tenant com seu banco, auth por API key, exportação PDF/XLSX e publicação via SFTP. É a stack enterprise mais pedida do mercado, em código que recebe commit meu toda semana.

  • 10 arquivos de teste JUnit: serviço, guard de paths remotos, publisher SFTP, exposição do actuator.
  • Sentry plugado (variante Jakarta do Spring Boot 3). Erro rastreado, não log perdido.
  • 303 linhas de ReportService com tratamento de formato, erro 400 claro e 500 instrumentado.

02maestro destaque

Bash · Python · JSON Schema · MCP

Harness de multi-orquestração de agentes: N demandas em paralelo, cada demanda numa pipeline de etapas em série. O maestro nunca executa. A etapa nunca decide o próximo passo.

  • 9 runs reais com handover e relatório por etapa, 5 provas executáveis e 16 testes de harness.
  • Portão nas duas pontas: critério auditado antes do despacho, handover auditado depois. Contratos em JSON Schema.
  • Custo medido: agrega tokens e gasto por demanda. Conversa com o Kai pelo laço pegar, concluir e falhar.

03kai destaque

TypeScript · Hono · React 19 · Postgres · MCP · Vitest

Board kanban onde agentes executam e o humano decide. O agente pega a task, prova o feito e relata o gasto. Sozinho, de ponta a ponta. Em produção, em domínio privado.

  • 73 arquivos de teste, 21 migrations, typecheck duplo. API e MCP na mesma porta.
  • 5 colunas com limite de WIP, métrica SLE e tokens com escopo de leitura e escrita.
  • Motor da esteira lb-ops: fila os incidentes do gateway, o agente diagnostica, o humano aprova o done.

04lb-proxer em produção

TypeScript · Node 22 · Vitest · 2 front-ends · Docker · Coolify

Gateway/load balancer multi-provider de LLMs em produção, em domínio privado. Roteia por modelo, escolhe a assinatura certa, falha com mensagem útil. Releases no formato TL;DR → Por quê → Impacto → Como não repete.

  • Suite 2306/2306 verde na v0.4.0, com 23 testes novos travando a matriz caminho×modelo×stream.
  • 184 arquivos de teste, typecheck limpo, deploy com prova viva em produção.
  • Observabilidade própria: endpoint de métricas e painel estilo NOC. Conclusão antes do gráfico.

05atendimentokonfig K8s GitOps

TypeScript · Vitest · K8s RKE2 · Rancher · Fleet · Kustomize · Supabase PG · Redis

Sistema de atendimento com deploy GitOps de verdade: o merge gera a imagem, o CI commita o digest no manifesto, o Fleet aplica. Homologação espelha produção de propósito. O CI quebra se os manifestos divergirem.

  • 301 arquivos de teste, incluindo regra financeira BR (parse de “1.234,56”).
  • Infra documentada em INFRA.md + PIPELINE.md: namespaces, réplicas, sealed secrets, runners.
  • Mentoria prática: ensinei operação K8s hands-on neste cluster. Sei explicar, não só aplicar yaml.

06auditoria agentes + MCP

TypeScript · Claude Agent SDK · MCP · Vitest · coverage v8

Módulo fiscal com agentes de IA operando ferramentas reais: harness com teto de chamadas, retry travado e superfície explícita de tools. Teste de contrato compara cada ferramenta contra SQL independente, e inclui tentativa de injeção.

  • 138 arquivos de teste no back/front, com coverage configurado.
  • Fronteira com a SDK isolada num arquivo só. O resto do código não sabe que IA existe.

07FastDocs MCP server

TypeScript · Fastify · Next.js · MCP SDK · React Flow

Servidor MCP de documentação AI-first: detecta framework do repo, monta grafo de docs, expõe Postman Lite e GitHub Action. Detector com TDD por fixtures (tmpdir real, setup/teardown).

  • Detector testado para next-app-router, pages, NestJS e Express.

08railyard plataforma

TypeScript · pnpm + Turbo · Prisma · Vitest · Docker

PaaS self-hosted estilo Railway para uso próprio: git push, build zero-config, HTTPS, databases em um clique, environments efêmeros por PR. M0–M2 prontos, com design docs e critério de aceite por task.

  • 125 arquivos de teste; tasks com checkbox e ordem de construção.
  • Quem constrói plataforma entende deploy, não só usa.

03 · Como eu trabalho

Método: teste primeiro, número sempre

TDD e testes

Teste não é cerimônia, é trava. Cada release do gateway lista quantos testes novos entraram e o placar final. Regra de dinheiro (conciliação, transferência) tem teste de borda em pt-BR.

2306/2306 · 301 suites · JUnit no Java · anti-SQL-injection

CI/CD

Todo merge roda migrations, tipos, testes e build. Verde vira release + imagem assinada + digest commitado, e o Fleet aplica sem ninguém digitar nada. Deploy é commit, não ritual.

PIPELINE.md · digest como gatilho · cutover planejado

Resiliência

Gateway escolhe assinatura pelo modelo, falha com 400 explicativo em vez de relay suicida, e expõe saúde e métricas. Erro claro é feature.

failover · 400/401 úteis · health + métricas

Observabilidade

Painel próprio no padrão “conclusão antes do gráfico”. No Java, Sentry captura exceção com contexto. Incidente vira post-mortem, não déjà-vu.

/__metrics · painel NOC · Sentry 7.22

04 · Mentalidade IA First

IA como ferramenta de produção, não demo

Uso diário: agentes com travas, RAG validado ponta a ponta, gateway próprio para não depender de um provider. E código escrito com assistência de IA, revisado como se fosse de um junior talentoso: confio, verifico.

  • Harness de agentes com teto de chamadas e retry travado, sobre a Claude Agent SDK.
  • RAG fiscal com script e2e artigo→resposta fora do vitest (provedor real, validação real).
  • MCP servers próprios: documentação (FastDocs) e ferramentas fiscais (auditoria).
  • Gateway multi-provider em produção: troca de modelo sem trocar código.
